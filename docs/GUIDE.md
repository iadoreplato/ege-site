## 1. Сайт за одну минуту

Сайт состоит из трёх частей:

| Часть | Где | Что вы там меняете |
|---|---|---|
| **Контент** | `src/content/*.json` | слова, упражнения, задания. **90 % правок здесь** |
| **Код** | `src/components/*.tsx` | как показывать контент, новые виды упражнений |
| **Оформление** | `src/styles.css` | цвета, размеры, отступы |

Главная идея: **JSON говорит, ЧТО показать, код решает, КАК показать.**
Например, в JSON написано `"type": "choose"`, и код знает, что надо нарисовать предложение с кнопками выбора.
Поэтому новый юнит или модуль можно сделать, не трогая код вообще.

## 2. Рабочий день

### Один раз на новом компьютере
1. Установить Node.js (версии 18 или новее) с сайта nodejs.org.
2. Открыть папку проекта в VS Code → меню Terminal → New Terminal.
3. Выполнить `npm install`. Команда скачает библиотеки, это займёт пару минут.

### Каждый раз
1. **Запустить сайт:** `npm run dev`, затем открыть адрес из терминала (обычно http://localhost:5173).
   Пока команда работает, сайт сам обновляется после каждого сохранения файла.
   Остановить: в терминале нажать `Ctrl + C`.
2. **Поправить** нужный файл и сохранить (`Cmd + S`).
3. **Посмотреть** результат в браузере.
4. **Проверить, что ничего не сломалось:** `npm run build`. Если в конце написано `✓ built`, всё хорошо.
   Строчку `Some chunks are larger than 500 kB` можно не замечать: это просто совет, а не ошибка.
5. **Сохранить в git** (раздел ниже).

Go Live в VS Code с исходниками не работает. Для Go Live откройте `dist/index.html` после `npm run build`.

### Git: сохранение версий
Git хранит историю всех изменений, к любой прошлой версии можно вернуться.
```
git status                         — что изменилось
git diff                           — сами изменения построчно
git add -A                         — подготовить все изменения к сохранению
git commit -m "Sport: unit 8"      — сохранить версию с подписью
git push                           — отправить на GitHub (сайт сам опубликуется)
```
Отменить несохранённые изменения в одном файле: `git restore путь/к/файлу`
(осторожно: эти правки пропадут насовсем).

### Публикация
- **GitHub Pages**: публикуется автоматически после каждого `git push` в ветку `main` (через пару минут).
  Ход публикации виден на GitHub во вкладке Actions.
- **Netlify**: если сайт подключён к Netlify, он тоже пересобирается сам.
  **Проверка «Check with AI» работает только на Netlify**: на GitHub Pages нет серверной части.

## 3. Рецепты

После любого рецепта: посмотрите страницу в браузере и выполните `npm run build`.

### Поменять цвет
Откройте `src/styles.css`. В самом начале, в блоке `:root`, все цвета подписаны по-русски.
Поменяйте значение, например `--color-accent: #C2643A;` на `--color-accent: #2E7D6B;`.
Цвет поменяется на всём сайте. Подобрать код цвета можно в любом «color picker» в интернете.

### Исправить опечатку или текст
Найдите текст поиском по проекту (в VS Code: `Cmd + Shift + F`) и исправьте его в JSON.
Если текст нашёлся в `.tsx`-файле, это общий текст интерфейса (кнопки, формулировки заданий). Его тоже можно править,
но формулировки заданий 1–4, 37, 38 должны остаться дословно как в демоверсии.

### Добавить слово в лексику
В нужном юните найдите блок в `vocab` (например, `"type": "list"`) и добавьте в `items` запись:
```json
{ "en": "to take up a sport", "ru": "начать заниматься спортом", "ex": "I took up tennis last year.", "key": ["take up", "took up"] }
```
- `key` — формы, которые надо подсветить (в примере глагол стоит в прошедшем времени, поэтому обе формы);
- неисчисляемое: добавьте `"uncountable": true`;
- несколько синонимов в одну строку: дайте им одинаковый `"group": 7` (любое число, не занятое соседями).

Слово автоматически попадёт в карточки и в «Match the pairs», если у него есть `ru`.

### Добавить упражнение
В `exercises` юнита добавьте объект. Формат пунктов для каждого вида — в [CODE.md, раздел 3.4](CODE.md#34-юнит-units).
```json
{ "type": "choose", "title": "Word choice in context", "instr": "Choose the correct word.",
  "items": [ ["She {won|beat} her opponent easily.", "beat"] ] }
```
По правилам проекта: 10–15 пунктов, правильный ответ стоит на разных местах без повторяющегося рисунка.

### Добавить юнит
Скопируйте целиком объект юнита из `units` (от `{` до парной `}`), вставьте после последнего, поставьте запятую между ними,
поменяйте `num` и содержимое. Юнит сам появится в меню и оглавлении.
Не забудьте: в каждом юните есть задание 2 (`"type": "ad"` в `speech`).

### Добавить мини-повторение после юнита
В `reviews` модуля добавьте объект с `"after": <номер юнита>` (формат в [CODE.md, 3.6](CODE.md#36-мини-повторения-reviews)).
Оно само встанет в меню после этого юнита.

### Новый модуль
1. Скопируйте `src/content/sport.json` → например, `src/content/travel.json`.
2. Поменяйте `id` (латиницей, без пробелов: `"travel"`), `title` и весь контент.
3. В `src/App.tsx` добавьте импорт и строку в массив:
   ```tsx
   import travelData from "./content/travel.json";
   ...
   const topics = [sportData, russiaData, travelData] as unknown as Topic[];
   ```
4. Модуль появится в меню как «Module 3».

### Письмо (задание 37) от девушки
Если отправитель — девушка с новым именем, откройте `src/components/Speech.tsx` и добавьте имя в строку
```tsx
const HER = new Set(["Ella", "Sophia", "Helen"]);
```
Иначе в задании будет написано «answer his questions».

### Добавить фото к заданию 2, 3 или 4
Положите файл в `public/photos/` с именем из списка в `public/photos/README.md`
(например, `sport-u1-task2.jpg`). Подходят .jpg, .jpeg, .png, .webp. Пока фото нет, показывается иконка.
Если вы добавили новые задания, допишите их имена в этот README. Имя строится так:
`<id модуля>-u<номер юнита>-task<номер задания>`, для задания 4 ещё `-photo1` / `-photo2`.

### Добавить задание на аудирование
1. Положите файл задания в `src/content/listening/` с именем `<id модуля>-u<номер юнита>.json`
   (образец — `sport-u1.json`, поля описаны в `docs/CODE.md`, раздел 3.7). `module` и `unit` внутри должны совпадать с юнитом.
2. Положите запись в `public/audio/<id>.mp3` и добавьте её в `public/audio/manifest.json` с `"mock": false` и `seconds`.
3. `npm run dev` → откройте юнит → вкладка Listening.
   Пока записи нет (или `mock: true`), вкладки Listening у юнита нет — это нормально.
4. Вопросы для обсуждения под заданием — поле `"discuss": ["…", "…", "…"]`. Нет поля — нет блока Discuss.

### Добавить задание на чтение
1. Положите файл в `src/content/reading/` с именем `<id модуля>-u<номер юнита>.json` (поля — `docs/CODE.md`, раздел 3.7).
2. Проверьте формат и ключ: `node scripts/check-reading.mjs`.
3. `npm run dev` → откройте юнит → вкладка Reading.

### Названия разделов, номера ЕГЭ и русские формулировки
Всё это в `src/content/sections.json`: `label` — название вкладки, `ege` — номера заданий, `types` — подписи
типов в заголовке карточки, `ru` — русская формулировка над заданием (дословно из демоверсии).
Порядок `types` не меняйте: по нему считается номер в метке «EGE …» (у Speaking reading = 1, ad = 2…).

Ученик сам видит свой результат: отметка «✓ done» в оглавлении (проверены Listening и Reading юнита)
хранится только в его браузере.

### Добавить тренировочный вариант (Practice tests)
Вариант N — это 11 файлов с `"module": "variant"` и `"unit": N` (образец — вариант 1):
1. Аудирование: `src/content/listening/variant-N-t1.json`, `-t2`, `-t3`; озвучка — `node scripts/make-audio.mjs` (тратит кредиты ElevenLabs).
   Пока записи нет, задание на сайте не показывается.
2. Чтение: `src/content/reading/variant-N-t10.json`, `-t11`, `-t12`.
3. Use of English: `src/content/use-of-english/variant-N-t19.json`, `-t25`, `-t30`.
4. Письмо: `src/content/writing/variant-N.json` (email и essay); устная часть: `src/content/speaking/variant-N.json`
   (reading, ad с четырьмя образцами вопросов в `questions`, interview, photo).
5. Проверка: `node scripts/check-variants.mjs`, `node scripts/check-reading.mjs`, `node scripts/make-audio.mjs --check`.
6. Вариант сам появится в меню «Practice tests» и на странице `#/free`.

### Демо-кабинеты (модель)
Сайт пока работает как модель: вход без пароля (страница `#/login`), данные лежат только в браузере.
- Пользователи и вымышленная история занятий — `src/content/demo.json` (`users`, `homework`, `results`; `daysAgo` — сколько дней назад).
  Новый демо-ученик: строка в `users` с `"teacher": "daria"`.
- Начать модель с чистого листа: в браузере очистите данные сайта (или выйдите и войдите заново — история из `demo.json` останется).
- Шкала перевода баллов — `src/content/scale.json` (сейчас 2026 год, источник указан в файле; сверьте с fipi.ru).
- Тексты главной страницы — `src/components/Pages.tsx`: два раздела — `PATHS`, три шага — `STEPS`, заголовок и кнопки — в функции `Landing`.
  Цифры в тёмной полосе (варианты, юниты, слова) сайт считает сам.
- Подсказки учителю в кабинете («Needs attention») и границы цветов (80 % и 60 %) — `src/components/Cabinet.tsx`.

### Картинка-иконка
Иконки лежат в `public/img/` (Fluent Emoji). В JSON пишется имя файла без `.svg`: `"img": "soccer_ball"`.
Новую иконку можно скачать из Fluent Emoji (лицензия MIT) и положить в ту же папку.

### Кролик
Всё про кролика — в `src/components/Rabbit.tsx`:
- **как часто выглядывает**: функция `Peeker`, строка `random(240, 300) * 1000` (секунды × 1000).
  Например, `random(120, 180)` — раз в 2–3 минуты;
- **откуда выглядывает**: `const EDGES = ["bottom", "bottom", "left", "right"]`. Убрать слово — кролик перестанет выглядывать с этого края;
- **фразы похвалы**: функция `cheer` (тексты в кавычках);
- **фразы на обложке**: `COVER_REACTIONS`;
- **приветствие в юните**: `src/components/Topic.tsx`, строка с `rabbitSay("curious", ...)`;
- **цвета**: `--color-rabbit-*` в `styles.css`.

### Включить проверку «Check with AI» (YandexGPT)
Проверка работает через YandexGPT от Яндекса: доступен в России без VPN, оплата в рублях российской картой.

**Шаг 1. Yandex Cloud**
1. Зайдите на console.yandex.cloud под своим Яндекс ID.
2. Создайте платёжный аккаунт (Биллинг → Создать аккаунт), привяжите карту. Новым пользователям обычно дают стартовый грант.
   Сразу настройте бюджет с уведомлением (Биллинг → Бюджеты), чтобы контролировать расходы.
3. Откройте каталог `default` (или создайте свой) и скопируйте его **ID** — строка вида `b1g...` рядом с названием каталога.

**Шаг 2. Ключ**
1. В каталоге: Identity and Access Management → Сервисные аккаунты → Создать сервисный аккаунт.
   Имя любое (например, `ege-checker`), роль — `ai.languageModels.user`.
2. Откройте этот аккаунт → «Создать новый ключ» → «Создать API-ключ».
   Если спросят область действия, выберите `yc.ai.languageModels.execute`.
3. Скопируйте секретный ключ сразу: второй раз его не покажут.

**Шаг 3. Netlify**
1. Подключите проект к Netlify, если ещё не подключён: netlify.com → Add new site → Import from Git → репозиторий на GitHub.
2. Netlify → Site configuration → Environment variables → добавьте:
   - `YANDEX_API_KEY` = секретный ключ из шага 2;
   - `YANDEX_FOLDER_ID` = ID каталога из шага 1;
   - по желанию `YANDEX_MODEL`: по умолчанию `yandexgpt/latest` (YandexGPT Pro, проверяет лучше);
     `yandexgpt-lite/latest` дешевле, но заметно хуже находит ошибки.
3. Deploys → Trigger deploy, чтобы новые переменные заработали.

**Шаг 4. Проверка**
Откройте сайт на адресе Netlify (…netlify.app), задание 37 или 38, напишите текст и нажмите «Check with AI».
Ответ приходит за 10–60 секунд.

Если что-то не так, сайт покажет сообщение:
| Сообщение | Причина |
|---|---|
| `not connected yet` | сайт открыт не на Netlify (например, на GitHub Pages) |
| `not set up yet: YANDEX_API_KEY …` | не добавлены переменные в Netlify или не было нового деплоя |
| `YandexGPT error 401` / `403` | неверный ключ или у сервисного аккаунта нет роли `ai.languageModels.user` |
| `YandexGPT error 400` | неверный `YANDEX_FOLDER_ID` или имя модели |
| `YandexGPT error 429` | слишком много проверок сразу, попробуйте через минуту |

Проверить у себя на компьютере: `npm i -g netlify-cli` (один раз), затем `netlify dev` вместо `npm run dev`
(переменные Netlify подтянутся сами после `netlify link`).

Ключ никогда не кладите в код и в git: он хранится только в настройках Netlify.
Оценка ИИ — примерная, по критериям ФИПИ, а не официальная.

**Как устроен промпт** (если захотите его поправить): `netlify/functions/check.mjs`, константа `CRITERIA` — критерии ФИПИ
для каждого задания по-русски, функция `systemPrompt` — роль эксперта и порядок проверки.
Баллы за пределами шкалы, итог и правило «K1 = 0 → 0» код исправляет сам, их в промпте трогать не нужно.

## 4. React на примерах этого проекта

### Компонент
Функция, которая возвращает кусок интерфейса. Её имя пишется с большой буквы.
```tsx
// src/components/Speaking.tsx
export default function Speaking({ tasks }: { tasks: SpeakTask[] }) {
  return <>{tasks.map((t, i) => <div className="exercise" key={t.title}>...</div>)}</>;
}
```
Пользоваться компонентом можно как тегом: `<Speaking tasks={unit.speaking} />`.

### JSX
Это HTML-подобная разметка прямо в коде. Отличия от HTML:
- `className` вместо `class`;
- в `{ }` пишется JavaScript: `{unit.title}` вставит название юнита;
- `<>...</>` — «пустая обёртка», когда нужно вернуть несколько элементов.

### Props (входные данные)
То, что компонент получает «сверху». В `<UnitView unit={...} topic={...} />` props — это `unit` и `topic`.
Компонент props не меняет, только читает.

### Показ по условию
```tsx
{unit.speaking && <Speaking tasks={unit.speaking} />}       // показать, только если есть speaking
{checked ? "Try again" : "Check answers"}                    // одно из двух
```

### Список из массива
```tsx
{items.map((x, i) => <li key={i}>{x}</li>)}
```
`map` превращает каждый элемент массива в кусок разметки. `key` — уникальная метка для React,
чтобы он понимал, какой элемент списка какой. Без неё React выдаст предупреждение в консоли.

### Хуки
Специальные функции, имя начинается с `use`:
- `useState` — память компонента: `const [checked, setChecked] = useState(false)`.
  Вызов `setChecked(true)` запоминает новое значение и перерисовывает компонент;
- `useEffect` — действие «помимо рисования»: таймеры, подписка на события. `return () => ...` внутри — уборка;
- `useRef` — ссылка на элемент страницы или значение, которое не вызывает перерисовку;
- `useMemo` — запомнить результат вычисления, пока не поменялись входные данные (в `MatchPairs`);
- свой хук `useLook` в `Rabbit.tsx` — голова кролика следит за мышкой.

Правило: хуки вызываются только в начале компонента, не внутри `if` и циклов.

### Как одно упражнение работает целиком (`Exercises.tsx`, `Pick`)
1. `useState({})` хранит выбор ученика: `{ 0: "court", 3: "beat" }` (номер пункта → вариант).
2. Нажатие на вариант вызывает `setPick({ ...pick, [i]: o })`: React перерисовывает, кнопка становится «выбранной».
3. `score` считается заново при каждой перерисовке: сколько выборов совпало с ответами.
4. «Check answers» ставит `checked = true`, и кнопки красятся в `option--correct` / `option--wrong`.
5. Заодно вызывается `cheer(score, total)`, и кролик хвалит или подбадривает.

## 5. TypeScript: что нужно знать

TypeScript — это JavaScript с «типами»: описаниями, как выглядят данные.
Перед сборкой он проверяет, что вы не перепутали поля. Файлы `.ts` и `.tsx` написаны на нём (`.tsx` — с разметкой).

```ts
interface Unit { num: number; title: string; speaking?: SpeakTask[] }
```
- `num: number` — число; `title: string` — строка;
- `?` — поле может отсутствовать;
- `SpeakTask[]` — массив заданий;
- `any` — «что угодно, не проверять».

Если `npm run build` пишет `error TS...`, это TypeScript нашёл несоответствие. В сообщении есть файл и номер строки.

## 6. Когда что-то сломалось

| Признак | Что делать |
|---|---|
| Белый экран | Откройте консоль браузера (`Cmd + Option + J` в Chrome) и прочитайте красную ошибку. Часто это ошибка в JSON |
| `npm run build` пишет `error TS2339 ... file.tsx:12:5` | Ошибка в файле `file.tsx`, строка 12. Чаще всего опечатка в имени |
| `Unexpected token` / `JSON` в ошибке | Сломан JSON: лишняя или пропущенная запятая, кавычки. VS Code подчёркивает такие места красным |
| Блок не показывается | Проверьте `type`: при опечатке (`"tabel"` вместо `"table"`) блок молча пропадает |
| Слово не подсвечивается | В `key` должна быть точная форма из текста (`"took up"`, а не `"take up"`) |
| Ответ ученика не засчитывается | Добавьте вариант через `/` в ключ: `"since I last went/since I went"` |
| «The checking service is not connected yet» | ИИ-проверка не подключена (см. рецепт) или сайт открыт не на Netlify |
| Хочется всё вернуть | `git restore .` отменит все несохранённые изменения (насовсем!) |

Частые ошибки в JSON:
```
{ "en": "a coach", "ru": "тренер", }     ← запятая перед } — ошибка
{ "en": "a coach" "ru": "тренер" }      ← нет запятой между полями — ошибка
{ "en": "a "pro" player" }              ← кавычки внутри текста — ошибка; пишите «» или \"
```

## 7. Словарь

| Слово | Значение |
|---|---|
| **компонент** | функция, которая рисует кусок интерфейса (`Header`, `UnitView`) |
| **props** | входные данные компонента |
| **state, состояние** | память компонента (`useState`) |
| **хук** | функция `use…`, дающая компоненту память и действия |
| **JSX** | HTML-подобная разметка внутри кода |
| **рендер, перерисовка** | React заново вызывает компонент и обновляет экран |
| **JSON** | формат данных: `{ "поле": "значение" }`, массивы в `[ ]` |
| **массив** | список: `["a", "b", "c"]`; счёт с нуля: `a` — нулевой |
| **объект** | набор полей: `{ "en": "...", "ru": "..." }` |
| **импорт / экспорт** | `export` — сделать функцию доступной другим файлам, `import` — взять её из другого файла |
| **тип** | описание вида данных (TypeScript) |
| **CSS-класс** | имя в `className`, по нему CSS оформляет элемент |
| **БЭМ** | правило имён классов: `блок__элемент--модификатор` |
| **CSS-переменная** | `--color-main`: значение задаётся один раз, используется везде через `var(--color-main)` |
| **сборка (build)** | превращение исходников в готовый сайт в папке `dist` |
| **деплой** | публикация сайта в интернете |
| **localStorage** | маленькая память браузера; тут хранится последняя открытая страница |
| **серверная функция** | код, который работает на сервере, а не у ученика (`check.mjs`) |
| **API-ключ** | секретный пароль для доступа к YandexGPT; хранится только в Netlify |
| **git, коммит** | система версий; коммит — сохранённая версия с подписью |

## 8. Правила, которые лучше не нарушать

1. **Не переименовывайте поля в JSON** (`en`, `ru`, `items`, `type`…). Код ищет их по имени.
   Новое поле добавить можно: код его просто не увидит, пока вы его не научите.
2. **Цвета только через переменные в `:root`**, не пишите `#C2643A` прямо в классах.
3. **После правок — `npm run build`.**
4. **Не кладите в проект секреты** (ключи, пароли): git отправит их на GitHub.
5. **Не добавляйте сбор данных учеников** (аккаунты, отправку ответов на сервер).
6. **В `styles.css` не используйте `calc(var(...))` и `color-mix(...)`**: сборщик на них зависает.
7. **Коммит перед большими правками**: если что-то пойдёт не так, к нему можно вернуться.
8. Правила содержания (уровень, форматы, число пунктов) записаны в `CLAUDE.md`, раздел «Правила контента».

## 9. С чего начать изучение кода

Порядок, в котором читать файлы. Каждый следующий опирается на предыдущий:
1. `src/types.ts` — как выглядят данные (20 строк).
2. Один юнит в `src/content/sport.json` — живые данные.
3. `src/App.tsx` — как выбирается страница.
4. `src/components/Speaking.tsx` — самый маленький компонент (12 строк).
5. `src/components/Exercises.tsx` — упражнения: `useState`, проверка, кролик.
6. `src/components/Topic.tsx` — как собирается страница юнита из вкладок.
7. `src/components/text.tsx` — как текст из JSON превращается в подсвеченный.
8. `src/components/Rabbit.tsx` — `useEffect`, `useRef`, свой хук, события.

Полезное упражнение: поменяйте что-нибудь маленькое (текст кнопки «Check answers» в `Exercises.tsx`),
посмотрите результат, потом верните через `git restore src/components/Exercises.tsx`.

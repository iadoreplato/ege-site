## 2. Как сайт запускается

```
index.html  →  <div id="root"> и <script src="/src/main.tsx">
main.tsx    →  подключает tailwind.css и styles.css, рисует <App /> внутри #root
App.tsx     →  читает адрес страницы (#/...), решает, какой компонент показать
               ├── <Header>        всегда
               ├── одна из страниц: <Cover> | <UniversalPage> | <TypologyBank> | <UnitView> | <Revision> | <Review>
               ├── <Praise>        всегда (кролик-похвала; появляется по событию)
               └── <Peeker>        на всех страницах, кроме главной (выглядывающий кролик)
```

Данные текут **сверху вниз**. `App` импортирует JSON и передаёт нужные куски дочерним компонентам
через props (например, `UnitView` получает один юнит), а те передают дальше ещё более мелкие куски.

Есть одно исключение: кролик-похвала. Упражнения не передают ему данные напрямую.
Они вызывают функцию `rabbitSay(...)` или `cheer(...)`, та отправляет событие `rabbit-say` на всё окно,
а компонент `Praise` это событие слушает. Так любое место сайта может «позвать» кролика.

## 3. Данные: JSON с контентом

Главный принцип: **JSON содержит только смысл, код решает, как это выглядит.**
Поэтому в JSON нет HTML, цветов и значков. Названия полей менять нельзя: от них зависит код.

### 3.1. Текст с разметкой (`RichText`)

Любой текст в JSON может быть:
- **просто строкой**: `"Our coach makes us train hard."`
- **объектом**, если в тексте есть особые места:
  ```json
  { "text": "win + a match · beat + a person", "key": ["win", "beat"], "example": ["We beat Spartak."], "uncountable": true }
  ```
  | Поле | Что значит | Как выглядит на сайте |
  |---|---|---|
  | `text` | сам текст (обязательно) | |
  | `key` | ключевые элементы: целые слова/фразы; `"-ing"` означает окончание слова | подсветка (`<mark class="key-element">`) |
  | `example` | языковые примеры (точные куски текста) | курсив (`<em class="language-example">`) |
  | `uncountable` | неисчисляемое | значок **U** после текста |

Особые знаки внутри текста:
| Знак | Где | Что делает |
|---|---|---|
| `\n` | везде | перенос строки |
| `___` | шаблоны ответов, упражнения | линия-пропуск или поле ввода |
| `{a\|b\|c}` | упражнение `choose`, тест `contrast` | кнопки выбора прямо в предложении |
| `{30}`, `{31}`… | тексты заданий 30–36 | номер пропуска |
| `{A}`…`{F}` | текст задания 11 | пропуск с выпадающим списком 1–7 |
| `sb`, `sth`, `+ -ing`, `+ noun`, `(informal)`, `(formal)`, `(BrE)`, `(AmE)`, `(v)`, `(n)` | везде | автоматически оформляются как грамматическая помета |

### 3.2. `universal.json`: универсальный блок

```json
{
  "id": "...", "title": "...", "subtitle": "...", "source_note": "...",
  "cover_pics": ["clipboard", ...],
  "pages": [ { "kick": "...", "title": "...", "lede": "...", "pics": [...], "blocks": [ ... ] } ],
  "frames": { "t4": [...], "t37": [...], "t38": [...] }
}
```
- `pages`: страницы раздела «The exam» (сейчас 11). `kick` — надпись над заголовком, `lede` — подзаголовок,
  `pics` — картинки в баннере, `blocks` — содержимое.
- `frames`: шаблоны ответов, общие для всех модулей; каждая строка — `["1 · Greeting", "Hi, ___! ..."]`.
  Они показываются в заданиях 4, 37, 38 по кнопке «Show support».

**Блоки страниц (`blocks`)**: компонент `Block` в `Universal.tsx` выбирает вид по полю `type`.
`icon` во всех блоках — имя картинки из `public/img/` без `.svg`.

| `type` | Поля | Что показывает |
|---|---|---|
| `table` | `title`, `icon`, `head` (заголовки столбцов), `rows` (строки — массивы ячеек), `note`? | таблица в карточке |
| `stats` | `items`: `[число, подпись, комментарий]` | плитки с крупными цифрами |
| `criteria_detail` | `task`, `title`, `tone` (`"t37"` — цвет задания), `icon`, `scores` (баллы-столбцы), `rows`: `[критерий, [ячейки]]`, `aspects`?, `checklist`? | таблица критериев оценивания |
| `rules` | `title`, `icon`, `items` | список с тире |
| `wordcount` | то же, что `rules` | то же, в мягкой карточке |
| `demo` | `text` | формулировка задания из демоверсии |
| `steps` | `title`, `icon`, `items` | нумерованные шаги |
| `pairs` | `title`, `icon`, `items` | сетка пар («hit / heat») |
| `fipi` | `items`: `["no" или "yes", текст]` | «Watch out»: типичные ошибки из отчёта ФИПИ |
| `frame` | `title`, `icon`, `slots` (части схемы), `examples` | схема построения (например, вопроса) |
| `pool` | `title`, `icon`, `groups`: `[название, [фразы]]` | группы готовых фраз |
| `formula` | `items` | цепочка «шаг → шаг → шаг» |
| `rule` | `title`, `icon`, `items`: `["yes"/"no", текст]`, `note`? | правильно/неправильно |
| `a2list` | `title`, `items` | список-«чипсы» (уровень A2) |
| `skeleton` | `title`, `icon`, `lines`: `[метка, текст с ___]` | каркас ответа |
| `basis` | `title`, `items`: `[название, текст]` | основания для сравнения |
| `thesis` | `title`, `icon`, `items` | пронумерованный план |
| `compare` | `items`: `[заголовок, текст, пример]` | карточки сравнения |

Блок с неизвестным `type` просто не показывается (ошибки не будет).

### 3.3. Модуль (`sport.json`, `russia.json`)

```json
{
  "id": "sport",                       // часть адреса: #/sport/unit/1. Только латиница, без пробелов
  "title": "Sport & Healthy Lifestyle", "subtitle": "...",
  "cover_pics": [...],                 // картинки в оглавлении (показываются первые 6)
  "typology": [...],                   // банк сравнений для задания 4
  "units": [...],                      // юниты
  "revision": {...},                   // итоговое повторение модуля
  "reviews": [...],                    // мини-повторения после юнитов (необязательно)
  "ad_keys": [...],                    // образцы вопросов к заданию 2
  "photo_pool_base": { "describe": [...], "opinion": [...], "close": [...] },  // общие фразы к заданию 4
  "data_verbs": ["chose", "opted for", "picked"]                              // глаголы для задания 38
}
```
(Комментарии `//` здесь только для пояснения: в настоящем JSON комментариев быть не может.)

**`typology`**: каждая запись — массив из 10 элементов строго по порядку:
`[картинка A, название A, картинка B, название B, основание сравнения, плюсы A[], минусы A[], плюсы B[], минусы B[], как описать разницу]`.

**`ad_keys`**: `[название рекламы, "образцы вопросов через ·"]`. Образец находится по точному совпадению
с `title` рекламы или по первому слову названия.

### 3.4. Юнит (`units[]`)

```json
{
  "num": 1, "title": "...", "lede": "...", "pics": [...],
  "vocab": [...],        // вкладка Vocabulary
  "exercises": [...],    // вкладка Practice
  "speaking": [...],     // вкладка Speaking (необязательно: если поля нет, вкладка скрыта)
  "speech": [[...], [...]],  // вкладка Exam tasks: массив групп заданий
  "cards": { "gaps": [...], "contrast": [...] }   // быстрый тест во вкладке Memorise (необязательно)
}
```

**Запись лексики (`VocabItem`)**: одно слово или выражение.
| Поле | Обязательно | Что значит |
|---|---|---|
| `en` | да | слово/фраза по-английски; глаголы с `to` |
| `ru` | да (для карточек) | перевод. Без перевода слово не попадёт в карточки |
| `ex` | нет | пример употребления |
| `key` | нет | формы ключевого элемента для подсветки в `en` и `ex` |
| `uncountable` | нет | `true`, если неисчисляемое |
| `group` | нет | одинаковое число у соседних записей → одна строка «a competitor · an opponent · a rival» |
| `img` | для блоков с картинками | имя картинки из `public/img/` |
| `sports`, `prep`, `note` | только в блоке `venues` | «какие виды спорта», предлог, примечание |

**Блоки лексики (`vocab[]`)**: компонент `VocabBlock` в `Vocab.tsx`.
| `type` | Поля | Что показывает |
|---|---|---|
| `list` | `title`, `items` | список слов с переводом и примером |
| `expressions` | `title`, `items` | то же с пометкой B2+ |
| `pics` | `title` (может быть RichText), `cols` (число колонок), `items` с `img` | сетка картинок со словами |
| `gpd` | `groups`: `[ЗАГОЛОВОК, подзаголовок, items[]]` | группы глаголов (go/play/do) с картинками |
| `venues` | `title`, `items` с `img`, `sports`, `prep`, `note` | таблица «где занимаются спортом» + готовая подсказка про pitch/court/rink |
| `note` | `title`, `text` | карточка-подсказка |
| `definition` | `text` | определение |
| `trio` | `items`: `[картинка, название, перевод, описание]` | три карточки рядом |

Подсказка «Tricky for Russian speakers» в блоке `venues` написана прямо в коде (`Vocab.tsx`), а не в JSON.

**Упражнения (`exercises[]`)**: `{ "type", "title", "instr", "items" }`. Компонент `ExerciseView` в `Exercises.tsx`.
| `type` | Формат одного пункта `items[i]` | Как проверяется |
|---|---|---|
| `collocation` | `["___ a record", ["break","set","hold","win"], "win"]` — фраза, варианты, ответ | нажатая кнопка = ответ |
| `choose` | `["Players need a {pitch\|field\|court}.", "court"]` | нажатая кнопка = ответ |
| `transform` | `["исходное", "KEYWORD", "начало ___ конец", "ответ"]` | введённый текст (см. `isCorrect`) |
| `translate` | `["русское предложение", "образец перевода"]` | не проверяется, кнопка показывает образец |
| `gaps` | `["предложение с ___", "ответ"]` | введённый текст; первая буква ответа — подсказка |

В ответах для ввода (`transform`, `gaps`, задания 19–29) можно писать варианты:
`"since I last went/since I went"` — подходит любой через `/`;
`"(have) been running"` — часть в скобках необязательна. Регистр, лишние пробелы, апострофы ’/' и точка в конце не важны.

**Вкладка Speaking (`speaking[]`)**: `{ "title", "task", "prompts"?: [...], "vocab": [...] }`.
Ничего не проверяется, это задания для работы в парах.

**Быстрый тест (`cards`)**: `gaps`: `["предложение с ___", "ответ"]`, `contrast`: `["предложение с {a|b|c}", "ответ"]`.

**Экзаменационные задания (`speech`)**: массив групп, например `[[interview, interview], [ad], [photo]]`.
Группы на сайте просто идут подряд. Компонент `SpeechView` в `Speech.tsx`.
| `type` | Задание | Поля |
|---|---|---|
| `reading` | 1, чтение вслух | `title`, `text` |
| `ad` | 2, вопросы по рекламе | `title`, `slogan`, `img`, `consider` («going to the camp»), `points` (4 пункта) |
| `interview` | 3, интервью | `topic`, `questions`: `[{ "q": вопрос, "pool": [подсказки] }]` (5 шт.), `trap`? (предупреждение) |
| `photo` | 4, фото | `project`, `p1`/`p2`: `[[картинки], "описание фото"]`, `focus`, `opinion`, `basis`, `pool`: `{describe, difference, pros, cons}` |
| `email` | 37, письмо | `sender`, `subject`, `text`, `ask` («about his trip»), `pool`: `{answers, questions}` |
| `essay` | 38, эссе | `subject`, `audience`, `q`, `data`: `[["вариант", %]]`, `problem`, `conclusion`, `focus4`, `pool` |

Особенности:
- В эссе вид данных чередуется внутри юнита: 1-е эссе юнита — таблица, 2-е — круговая диаграмма, 3-е — снова таблица
  (счётчик `essayIdx` в `Topic.tsx`). Проценты в `data` должны давать в сумме 100.
- Местоимение в письме (his/her) выбирается по имени отправителя: женские имена перечислены
  в `HER` в начале `Speech.tsx` (`Ella`, `Sophia`, `Helen`). **Новое женское имя нужно добавить туда.**

### 3.5. Итоговое повторение (`revision`)

```json
{
  "reading11": { "title", "text" (с {A}…{F}), "parts": [7 частей], "key": "A — 2 · B — 4 · … (1 is extra)" },
  "g1": [[19, "текст до", "текст после", "СЛОВО"], ...],   // задания 19–24
  "g2": [[25, "текст до", "текст после", "СЛОВО"], ...],   // задания 25–29
  "cloze": "текст с {30}…{36}",
  "opts": [[30, "вариант1", "вариант2", "вариант3", "вариант4"], ...],
  "keys": [["19–24", "ответ · ответ · …"], ["25–29", "…"], ["30–36", "30 — 3 overcome · 31 — 2 take · …"]],
  "transform": [...],   // как упражнение transform
  "translate": [...]    // как упражнение translate
}
```
Формат ключей строгий: код ищет «буква — цифра» (`A — 2`) и «номер — цифра» (`30 — 3`) с длинным тире `—`
и разделителем ` · `. Ответы 19–29 идут в `keys` в том же порядке, что пункты `g1`/`g2`.

### 3.6. Мини-повторения (`reviews[]`)

```json
{ "after": 2,                                  // после какого юнита (по num)
  "cloze": [ { "title", "text" (с {30}…), "opts": [[30, "в1","в2","в3","в4"], ...], "key": [3, 2, ...] } ],
  "transform": [...] }
```
Здесь `key` — просто массив правильных номеров вариантов по порядку пропусков.
Название формируется само: «Review: Units 1–2» (от юнита после предыдущего повторения до `after`).

### 3.7. Аудирование (`src/content/listening/<module>-u<N>.json`)

Один файл = одно задание для одного юнита. Сайт сам находит все файлы в папке (кроме `voices.json`)
и показывает задание на вкладке Exam tasks того юнита, у которого совпадают `module` (id модуля) и `unit` (номер).

```json
{ "id": "sport-u1",            // имя записи: public/audio/sport-u1.mp3 и ключ в manifest.json
  "module": "sport", "unit": 1,
  "task": 1,                   // 1 — говорящие A–F; 2 — True / False / Not stated; 3 — вопросы 3–9
  "title": "…",                // заголовок карточки
  "speakers": { "Speaker A": "male1" },   // голоса для озвучки (на сайте не показываются)
  "script": [ { "who": "Speaker A", "text": "…" } ],  // текст записи; виден только после Check (Transcript)
  "key": [1, 7, 4, 5, 2, 6],   // правильные ответы по порядку
  "options": ["…7 утверждений"]                          // только task 1
  "statements": ["…7 утверждений A–G"]                   // только task 2; key: 1 True, 2 False, 3 Not stated
  "questions": [ { "q": "…", "options": ["…", "…", "…"] } ]  // только task 3; key: номер варианта 1–3
}
```
Реплики `"who": "Announcer"` (диктор называет «Speaker A») в Transcript становятся подзаголовками.

`public/audio/manifest.json`: `{ "sport-u1": { "file": "sport-u1.mp3", "seconds": 416, "hash": "…", "mock": false } }`.
Карточка показывается, только если запись есть в manifest и `mock` равно `false`, и если mp3 открывается.
Длительность в плеере берётся из `seconds`.

## 4. Типы (`src/types.ts`)

Тип в TypeScript — описание того, как выглядят данные: какие поля есть и что в них лежит.
Типы ничего не делают на сайте. Они нужны, чтобы `npm run build` заметил ошибку,
например опечатку в названии поля.

| Тип | Что описывает |
|---|---|
| `Any` | «что угодно» (`any`): проверка типов отключена. Используется там, где структура JSON разнообразна (блоки, задания) |
| `RichText` | текст: строка или `{ text, key?, example?, uncountable? }` (раздел 3.1) |
| `VocabItem` | запись лексики (раздел 3.4) |
| `Universal` | весь `universal.json` |
| `Page` | страница универсального блока |
| `Unit` | юнит |
| `Review` | мини-повторение |
| `CardTests` | быстрый тест `{ gaps, contrast }` |
| `SpeakTask` | задание вкладки Speaking |
| `Exercise` | упражнение; `type` — одно из пяти слов (`"collocation" \| "choose" \| …`) |
| `Topic` | весь модуль |
| `ListeningTask` | задание на аудирование: `Listening1 \| Listening2 \| Listening3` (раздел 3.7). Общие поля одинаковые, а по значению `task` (1, 2, 3) TypeScript знает, какое ещё поле есть: `options`, `statements` или `questions` |
| `AudioInfo` | запись в `public/audio/manifest.json` |

Как читать запись типа:
- `title: string` — поле `title`, в нём строка;
- `speaking?: SpeakTask[]` — `?` значит «поле может отсутствовать», `[]` — «массив таких»;
- `[string, string][]` — массив пар строк;
- `Record<string, number>` — объект, где ключи — строки, значения — числа;
- `"a" | "b"` — либо `"a"`, либо `"b"`.

В `App.tsx` JSON приводится к типам через `as unknown as Topic[]`. Это значит «поверь, данные такого вида»:
TypeScript не сверяет JSON с типом полностью. Поэтому ошибку в JSON сборка может не поймать,
и её надо проверять глазами на сайте.

## 5. Адреса страниц (`src/route.ts`)

Какая страница открыта, хранится в адресе после `#`. Поэтому работают кнопка «Назад» и ссылки на конкретный юнит.

**Тип `View`**: описание открытой страницы. Поле `k` (kind, вид) выбирает вариант:
| `View` | Страница | Адрес |
|---|---|---|
| `{ k: "home" }` | обложка | `#/` |
| `{ k: "u", i }` | страница универсального блока (i с нуля) | `#/exam/1` |
| `{ k: "bank", t }` | банк сравнений модуля t | `#/sport/bank` |
| `{ k: "unit", t, i, tab }` | юнит i модуля t, вкладка tab | `#/sport/unit/3/practice` |
| `{ k: "rev", t }` | итоговое повторение | `#/sport/revision` |
| `{ k: "review", t, i }` | мини-повторение i | `#/sport/review/1` |

В `View` номера хранятся с нуля (как индексы массива), а в адресе с единицы.

| Функция / константа | Что делает |
|---|---|
| `TABS` | названия вкладок в адресе: `vocabulary, memorise, practice, speaking, exam-tasks`. Номер вкладки = позиция в массиве |
| `toHash(v, topics)` | `View` → адрес (`"/sport/unit/3/practice"`) |
| `fromHash(hash, topics, universal)` | адрес → `View`. Всё неизвестное или несуществующее открывает обложку |
| `label(v, topics, universal)` | человеческое название страницы (для кнопки «Continue» и вкладки браузера) |
| `reviewTitle(t, i)` | «Review: Units 1–2» |
| `Item` | тип строки оглавления: `{ v, no, title, tag? }` |
| `moduleItems(t, ti)` | все страницы модуля по порядку: банк → юниты (после нужных — мини-повторения) → Revision. Используется в меню и оглавлении |
| `samePage(a, b)` | та же ли это страница, не считая вкладки (для подсветки текущего пункта меню) |

## 6. Главный компонент (`src/App.tsx`)

Вспомогательные функции и константы вне компонента:
| Имя | Что делает |
|---|---|
| `universal`, `topics` | загруженные JSON. **Новый модуль добавляется в массив `topics`** |
| `LAST`, `SCROLL` | ключи в `localStorage` (память браузера): последняя открытая страница и прокрутка |
| `load(k)`, `save(k, v)` | безопасно читают/пишут `localStorage` (в приватном режиме просто ничего не делают) |
| `read(h)`, `name(v)`, `href(v)` | короткие обёртки над `fromHash`, `label`, `toHash` |
| `start()` | какую страницу открыть при запуске: из адреса, иначе ту, где ученик остановился, иначе обложку |
| `first` | результат `start()`, вычисляется один раз при загрузке |

Внутри `App`:
- состояние `view` — открытая страница; `last` — последняя страница (для кнопки «Continue» и метки «you stopped here»);
- эффект 1: слушает смену адреса (`hashchange`) и меняет `view`, прокручивает наверх;
- эффект 2: при смене страницы меняет заголовок вкладки браузера, запоминает страницу и позицию прокрутки;
- эффект 3: при запуске возвращает прокрутку на сохранённое место;
- `setTab(tab)` — переключение вкладки юнита: меняет адрес без добавления шага в историю «Назад»;
- разметка: `Header`, одна страница по `view.k`, `Praise`, `Peeker`.

Все данные ученика хранятся только в его браузере. На сервер ничего не отправляется,
кроме текста, который ученик сам отдаёт на ИИ-проверку.

## 7. Компоненты (`src/components/`)

Компонент — функция, которая получает props (входные данные) и возвращает разметку (JSX).
Ниже: что каждый файл экспортирует, какие у компонента props и что он делает.
**Внутренние** функции используются только в своём файле.

### `text.tsx`: показ текста и проверка ответов

| Имя | Вид | Что делает |
|---|---|---|
| `Text({ value, as?, className? })` | компонент | показывает `RichText`: подсвечивает `key`, выделяет `example`, оформляет `sb/sth/+ -ing`, добавляет значок U, превращает `\n` в перенос. `as` — какой тег использовать (`"span"` по умолчанию, можно `"li"`, `"p"`, `"div"`) |
| `plainText(value)` | функция | только текст без разметки |
| `Slots({ text })` | компонент | текст, где `___` превращены в линию-пропуск |
| `Img({ name, className? })` | компонент | картинка `public/img/<name>.svg` |
| `norm(s)` | функция | приводит ответ к единому виду: нижний регистр, один пробел, ’→', без точки в конце |
| `variants(key)` | функция | все допустимые варианты ответа из ключа (через `/`, с необязательными `(…)`) |
| `isCorrect(answer, key)` | функция | верен ли ответ ученика. Используется во всех полях ввода |
| `Chips({ items, className? })` | компонент | ряд «плашек» с текстом |
| `Card({ title, icon?, soft?, children })` | компонент | карточка с заголовком и иконкой; `soft` — мягкий фон |
| внутр. `GRAMMAR` | регулярное выражение | какие грамматические пометы оформлять |
| внутр. `keyRanges`, `allRanges` | функции | находят, где в тексте ключевые элементы и примеры |
| внутр. `Piece` | компонент | один кусок текста с одинаковым оформлением |

Как работает `Text`: для каждой буквы текста ставятся «флажки» (ключевое / пример / помета),
потом соседние буквы с одинаковыми флажками склеиваются в куски, и каждый кусок оборачивается в нужный тег.

`task`: `"37"`, `"38"`, `"S3"` (задание 3), `"S4"` (задание 4).

Как работает: отправляет `{ task, prompt, answer }` на `/api/check` (раздел 9) и получает номер проверки.
Потом каждые 3 секунды (`POLL_MS`) спрашивает, готова ли она; через 3 минуты (`POLL_LIMIT` попыток) сдаётся.
Если ученик ушёл со страницы, опрос останавливается (`alive`).

Показывает: итоговый балл; баллы и комментарий по каждому критерию; список ошибок
(было → стало, тип, объяснение); исправленную версию (раскрывается по нажатию); советы «What to work on».
После оценки зовёт кролика.

| Имя | Что это |

| типы `Criterion`, `Mistake`, `Result` | вид результата, который возвращает сервер |

| внутр. `wait(ms)` | пауза между опросами |

## 8. Стили (`src/styles.css`)

### Классы: что это здесь

В этом проекте **нет классов JavaScript** (`class X {}`): современный React пишется функциями.
Слово «класс» здесь означает **CSS-класс**: имя в `className="..."`, по которому CSS находит элемент и оформляет его.

### Именование по БЭМ

`блок__элемент--модификатор`:
- `exercise` — блок (упражнение);
- `exercise__header` — элемент блока (его шапка);
- `option--correct` — модификатор (вариант в состоянии «верно»).

Чтобы найти, где оформляется элемент: посмотрите `className` в компоненте и найдите этот класс в `styles.css`.

Все цвета заданы только там. Чтобы поменять цвет на всём сайте, поменяйте одно значение.

## 9. Серверная проверка ИИ

`netlify/functions/check.mjs` — маленькая программа, которая работает **на сервере Netlify**, а не в браузере.
Она нужна, потому что ключ API нельзя класть в код сайта: его увидел бы любой.

Проверку делает **YandexGPT** (Yandex Cloud, сервис Yandex AI Studio): он доступен в России без VPN,
оплачивается в рублях российской картой.

**Почему проверка в два шага.** Модель может думать дольше, чем Netlify разрешает работать функции (около 10 секунд).
Поэтому функция только запускает проверку у Яндекса («асинхронный режим»), а сайт потом сам спрашивает, готово ли:
```
POST /api/check  { task, prompt, answer }        → { done: false, id, note }   (или сразу { done: true, result })
GET  /api/check?id=…&task=…&note=…               → { done: false }  …  { done: true, result }
ошибка                                           → { error: "текст" } с кодом 400 / 502 / 503
```
`result`: `{ total, max, criteria: [{ id, name, score, max, comment }], errors: [{ wrong, right, type, explanation }], corrected, tips: [], note }`.

| Часть | Что делает |
|---|---|
| `TASKS` | критерии каждого задания (`["K1", "Task completion", 2]` — код, название, максимум) и лимиты слов для 37 и 38 |
| `CRITERIA` | официальные критерии ФИПИ по-русски для промпта (по страницам «Criteria» на сайте) |
| `ERROR_TYPES` | какие типы ошибок модель может указывать в каждом задании |
| `systemPrompt(task)` | промпт: роль эксперта ЕГЭ, критерии, порядок работы (найти ошибки → оценить по шкале → исправленная версия → советы), формат ответа JSON, защита от «команд» в тексте ученика |
| `words`, `sentences` | подсчёт слов (по правилам ЕГЭ) и предложений |
| `zeroResult(task, comment)` | результат «0 баллов» без вызова модели (слишком короткий ответ) |
| `finalise(task, text, note)` | разбирает ответ модели и **проверяет его кодом**: баллы не выходят за шкалу, сумма считается здесь, K1 = 0 → 0 за всё задание, пропущенный критерий = 0 с пометкой |
| `start(req)` | POST: проверяет запрос (задание известно, ответ ≤ 6000 символов), применяет лимиты слов, запускает модель |
| `poll(url)` | GET: узнаёт у Яндекса, готова ли проверка, и возвращает результат |
| функция по умолчанию | без ключей отвечает «not set up yet» (503); POST → `start`, GET → `poll` |
| `config.path` | адрес функции: `/api/check` |

Что делает код, а не модель (чтобы не было ошибок счёта):
- 37: меньше 90 слов → 0 баллов без проверки; больше 154 → проверяются первые 140 слов;
- 38: меньше 180 слов → 0; больше 275 → первые 250 слов;
- число слов (37, 38) и предложений (задание 4) считается в коде и сообщается модели;
- итоговый балл считается в коде.

Переменные окружения в Netlify:
| Переменная | Обязательно | Что это |
|---|---|---|
| `YANDEX_API_KEY` | да | API-ключ сервисного аккаунта Yandex Cloud |
| `YANDEX_FOLDER_ID` | да | ID каталога в Yandex Cloud (вида `b1g...`) |
| `YANDEX_MODEL` | нет | модель; по умолчанию `yandexgpt/latest` (YandexGPT Pro). Дешевле: `yandexgpt-lite/latest` (хуже проверяет) |

## 11. На заметку

Неиспользуемое. Его можно удалить, сайт от этого не сломается, если убрать вместе со всеми связями:
- `src/components/ui/` (button, card, dialog, marquee), `src/lib/utils.ts`, `src/tailwind.css`, `components.json`
  и библиотеки `tailwindcss`, `@tailwindcss/vite`, `clsx`, `tailwind-merge`, `class-variance-authority`,
  `lucide-react`, `tw-animate-css`. Это заготовка для компонентов shadcn/Magic UI, но сайт их не использует.
  Если удалять, нужно убрать и импорт `./tailwind.css` из `main.tsx`, и плагин `tailwindcss()` из `vite.config.ts`.

Особенности, о которых полезно знать:
- **PDF-версия** упоминается в правилах, но кода её сборки в этом репозитории нет.
- ИИ-проверка (YandexGPT) — примерная оценка. Модель иногда ошибается в подсчёте ошибок;
  итог по критериям надо воспринимать как ориентир, а не как балл эксперта.
- Многие данные типизированы как `any`, поэтому `npm run build` не найдёт ошибку в структуре JSON
  (например, пропущенное поле в задании). После правок контента смотрите страницу глазами.
- Формулировки экзаменационных заданий (`Speech.tsx`) и русские инструкции (`Revision.tsx`) записаны в коде,
  а не в JSON: они одинаковы во всех модулях.
- Подсказка «Tricky for Russian speakers» в `Vocab.tsx` (блок `venues`) тоже записана в коде и относится к спорту.
